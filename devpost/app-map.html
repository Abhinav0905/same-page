Finished-code reference

Same Page, mapped.

Two accounts enter separately. A small comparison engine turns them into five evidence-backed checks, then one editable message.

One action through the app

Three useful stops

1

src/App.tsx

Start at compare. It connects the button to both output paths and clears old results when either account changes.

2

src/lib/compare.ts

compareAccounts is the product's core. It checks each dimension, refuses to guess and counts the details that need review.

3

src/components/ComparisonCard.tsx

ComparisonCard turns one result into a readable status, explanation and two evidence quotes. The user sees the reason, not just a score.

Where the final message comes from

src/lib/confirmation.ts > buildConfirmation takes the same comparison result and asks one neutral question per unresolved detail. src/components/SharedConfirmation.tsx keeps it editable and handles copy failure without losing the text.

To change this, start here

Add a new sample

Edit src/data/roommateSample.ts. Keep the expected result explicit in tests/compare.test.ts.

Recognize another phrase

Edit the relevant function in src/lib/extractors.ts. Add an example that should match and one that must stay unknown.

Change the visual voice

Start with the variables and section rules in src/styles.css. Status meaning must still use text and icons, not color alone.

A practice to reuse

The requirement was concrete: the roommate sample must return two aligned details and three that need review. tests/compare.test.ts fixes that outcome in code, while tests/same-page.spec.ts proves a visitor can reach and use it in the browser.

On another project, write the visible result first. Then build the smallest path that makes that result true. It keeps a simple proof honest and stops setup work from replacing the product.
